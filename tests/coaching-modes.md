# 教练模式会话验收

在 Codex 和 Claude Code 各启用本仓库的 `acm-master`。每个场景从新会话开始，按顺序逐条发送用户输入。按行为和输出判断通过，允许两端措辞不同。

## 1. 提示逐级展开，随后切回完整解答

| 轮次 | 用户输入 | 通过条件 |
| --- | --- | --- |
| 1 | 有 n 个整数，求长度恰好为 k 的连续子数组的最大和，1 ≤ k ≤ n。输入两行，第一行 n k，第二行 n 个整数。只给第一个提示。 | 给一个能动手尝试的提示，例如画出两个相邻窗口。到此停下，保留完整推导和代码，也无需选择语言。 |
| 2 | 我画出了两个相邻的窗口。 | 可以回应这一步或请用户说说观察结果。用户尚未要求升级，回复应停留在当前层。 |
| 3 | 再给一级提示。 | 只推进一层，例如引导比较哪两个元素发生了变化。用户仍有推导或实现留待自己完成。 |
| 4 | 现在给完整题解和 Python ACM 代码。 | 回到完整解题流程，直接使用 Python。将 `5 2` 和 `-5 -2 -3 -6 -1` 分两行输入，标准输出应为 `-5`。 |

## 2. 用反例诊断 WA 并复验修复

将下面整段作为一条用户消息发送。

~~~~text
请诊断这份 JS 提交的 WA。给定 n 个整数，判断能否选出不同位置的两个数，使其和为 k。1 ≤ n ≤ 100000，数组元素和 k 均在 −100000 到 100000 之间。输入两行，第一行 n k，第二行 n 个整数。输出 YES 或 NO。

```js
const [n, k, ...a] = require("fs").readFileSync(0, "utf8").trim().split(/\s+/).map(Number);
function solve() {
  const seen = new Set();
  for (const x of a) {
    seen.add(x);
    if (seen.has(k - x)) return "YES";
  }
  return "NO";
}
console.log(solve());
```
~~~~

- 给出合法的小反例并写清预期、实际输出。例如第一行 `1 6`，第二行 `3`，预期 `NO`，原程序输出 `YES`。其他能复现同一错误的合法反例也通过。
- 指出第一次偏差发生在处理当前元素时。先插入会让查询命中当前下标。最小修复是先查找，再插入。
- 在原反例上复验修复。也可核对第一行 `2 6`、第二行 `3 3` 仍输出 `YES`。分别标明原程序和修复程序的输出来自实际运行还是手推。

## 3. 同时请求反例诊断和提示

在新会话发送场景 2 的题面和代码，把开头的「请诊断这份 JS 提交的 WA」换为「我遇到 WA，只想要一级提示，先让我自己找反例」。回复可以引导用户检查集合在查询前包含哪些位置，应在给出具体反例、修补语句或完整代码前停下。再发送「现在给我完整诊断」，此时应满足场景 2 的判据。

## 4. 诊断证据不足

- 新会话发送「我的 JS 提交 WA 了，请给最小反例」。应索取题面、输入输出要求和提交代码，不能声称已经定位或复现。
- 新会话发送场景 2 的消息，先将循环内两条语句对调。对这份已修正的提交，应说明在给定题意和展示的代码下未能复现，可索取真实失败用例或实际提交版本。不得杜撰反例。
